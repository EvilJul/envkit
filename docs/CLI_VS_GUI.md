# EnvKit CLI vs GUI 对比

## 快速对比

| 特性 | CLI 版本 | GUI 版本 |
|------|----------|----------|
| **安装包体积** | 4-5 MB | 8-12 MB |
| **启动速度** | < 100ms | < 500ms |
| **内存占用** | 10-20 MB | 50-80 MB |
| **学习曲线** | 需要记忆命令 | 直观可视化 |
| **批量操作** | 支持脚本 | 多选操作 |
| **实时反馈** | 文本输出 | 进度条 + 动画 |
| **适用场景** | 服务器、自动化 | 日常使用、新手 |

---

## 使用场景

### CLI 版本适合

#### 1. 服务器环境
```bash
# 在远程服务器上快速部署
ssh user@server
curl -fsSL https://envkit.io/install.sh | bash
envkit install node python docker
```

#### 2. 脚本自动化
```bash
#!/bin/bash
# CI/CD 流程中使用
envkit install -f .envkit.yaml
envkit docker start postgres 16
```

#### 3. 高级用户
```bash
# 组合命令，批量处理
envkit list | grep "未安装" | xargs envkit install
```

#### 4. 资源受限环境
- 无桌面环境的系统
- 树莓派等嵌入式设备
- Docker 容器内

---

### GUI 版本适合

#### 1. 日常开发
- 直观的可视化界面
- 不需要记忆命令
- 一键式操作

#### 2. 新手用户
- 所见即所得
- 清晰的状态显示
- 友好的错误提示

#### 3. 团队协作
- 统一的视觉体验
- 易于培训新成员
- 减少错误操作

#### 4. 复杂配置
- 表单式配置
- 实时预览
- 图形化管理

## 混合使用

### 最佳实践

#### 开发环境（本地）
**推荐：GUI 版本**
- 可视化管理更直观
- 一键式操作更高效
- 减少命令行错误

#### 服务器环境（远程）
**推荐：CLI 版本**
- 通过 SSH 快速部署
- 脚本自动化
- 资源占用更小

#### CI/CD 流程
**推荐：CLI 版本**
- 易于集成到脚本
- 输出便于日志记录
- 无需图形界面

## 数据共享

### 两个版本完全兼容

```bash
# CLI 安装
envkit install node

# GUI 可以看到并管理
# 反之亦然
```

### 共享配置文件
```
~/.envkit/
├── config.yaml       # 配置
├── manifest.json     # 安装记录
└── settings.json     # 设置
```

```bash
# CLI 快速部署
envkit install -f dev-env.yaml

# 然后用 GUI 管理容器
# 启动 GUI -> Database 页面 -> 可视化管理
```

## 迁移指南

### 从 CLI 迁移到 GUI

**步骤：**
1. 安装 GUI 版本
2. 启动应用，自动识别已安装组件
3. 继续使用，无需额外配置

**注意事项：**
- 所有 CLI 安装的组件 GUI 都能管理
- 配置文件自动共享
- 无需重新安装任何环境

---

### 从 GUI 迁移到 CLI

**步骤：**
1. CLI 版本已内置
2. 打开终端，直接使用 `envkit` 命令
3. 所有 GUI 管理的组件都可用

**注意事项：**
- GUI 的配置 CLI 完全识别
- 可以在 CLI 中继续管理

## 总结

### 选择建议

| 如果你是... | 推荐版本 |
|------------|---------|
| 前端/全栈开发者 | GUI |
| 运维/DevOps | CLI |
| 初学者 | GUI |
| 高级用户 | CLI + GUI |
| 需要自动化 | CLI |

### 最佳实践

**同时安装两个版本！**
- 日常使用 GUI（直观方便）
- 脚本使用 CLI（自动化）
- 服务器使用 CLI（无桌面）
- 配置同步，无缝切换
